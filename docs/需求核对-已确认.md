## 一、角色与可见范围

### 1.1 角色映射（不新建角色）

| 口语称呼 | 系统角色 | 说明 |
|----------|----------|------|
| 管理员 | `admin`（系统管理员） | 全量查看；自建+交办；用户/模型等管理 |
| 部门管理员 | `dept_head`（部门负责人） | 与「团队管理员」同一套权限，不另建角色 |
| 团队管理员 | `dept_head`（部门负责人） | 同上 |
| 普通员工 | `member` | 只看自己相关数据 |
| 项目负责人 | `project_owner` | **保留**，但不算上述三类「管理员」；可交办，默认不能看全员周报 |

### 1.2 员工可见范围

员工可以看到：

- **全部项目**（项目管理列表与详情只读；仅本人负责的项目可改基本信息）
- 自己的周报
- 自己的任务（自建 + 交办给自己的 + 自己辅助的）
- **对自己任务的评价**、**对自己周报的评价**（本人可读）

员工**不能**看到他人的周报、任务、待办、评价。

### 1.3 管理员可见范围（`admin` / `dept_head`）

可查看团队范围内的：

- 全部周报、任务、待办、项目
- 部门待办汇总（成员未完成待办）

并可：

- 创建自己的任务（自建）
- 创建任务并指派（交办）给团队成员

## 二、员工写任务（需求 1）

员工本人写任务时须能：

1. **定目标**（做成什么样 / 做到什么程度）
2. **定时间**（截止日期等）
3. **定任务级别**（P0～P4）
4. **大模型结构化**：把口语描述整理成规范任务字段，并管控描述质量
5. **关联项目**
6. **计入待办**：保存后进入「我的待办」
7. **计入周报（方案 A，已确认）**：保存后**自动**写入**本周周报草稿**对应条目（人可改、可删）；不是写周报时才手动关联

---

## 三、员工写周报（需求 2）

员工本人写周报时须能：

1. **关联项目**
2. **大模型结构化**，把控周报质量
3. **定下一步计划**
4. 提交后，下一步计划进入**本人待办**（现有能力保留）

---

## 四、大模型贯穿（需求 4）

大模型须贯穿应用主链路，至少覆盖：

| 场景 | 能力 |
|------|------|
| 写任务 | 结构化、质量把控、建议优化 |
| 写周报 | 结构化、质量把控、建议优化 |
| 评价任务 | 对任务给出评价/建议；**执行人本人可见** |
| 评价周报 | 一阶段评价等；**作者本人可见**；管理员也可在周报工作台查看 |

无模型时继续规则兜底，不挡业务。
